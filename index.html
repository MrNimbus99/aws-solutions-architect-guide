Quiz 1 — Sample Question
A third-party vendor needs temporary access to specific S3 buckets in your AWS account for a data migration project lasting 3 months. What is the MOST secure approach?
  • ✓ Create an IAM role with S3 permissions, establish a trust relationship with the vendor's AWS account, and set a maximum session duration
  • Create an IAM user with access keys and share them with the vendor
  • Share your root account credentials with the vendor
  • Make the S3 buckets public for the duration of the project
Show Explanation
✓ Why correctCross-account IAM roles with trust relationships provide temporary, auditable access without sharing long-term credentials, and can be easily revoked.
✗ Why B is wrongSharing long-term access keys with an external party creates credentials that are difficult to rotate, audit, and revoke once the project ends.
✗ Why C is wrongSharing root account credentials is a critical security violation that provides unrestricted access far beyond the required S3 permissions.
✗ Why D is wrongMaking S3 buckets public exposes data to the entire internet, not just the vendor, violating data confidentiality.
Quiz 2 — Sample Question
A company runs a web application behind an Application Load Balancer with an Auto Scaling group. The security team requires that every instance launched by Auto Scaling must automatically have the correct firewall rules applied to restrict traffic to ports 80 and 443 from the ALB only. What is the BEST approach?
  • ✓ Attach security groups to the Auto Scaling launch template; instances automatically inherit them
  • Configure subnet-level NACLs to restrict inbound traffic to ports 80 and 443 from the ALB's IP range
  • Use an Auto Scaling lifecycle hook to trigger a Lambda function that attaches the correct security groups after each instance launches
  • Create an AWS Config rule to detect non-compliant security groups and automatically remediate them
Show Explanation
✓ Why correctWhen security groups are defined in an Auto Scaling launch template (or launch configuration), every instance launched by the group automatically inherits those security groups. This provides consistent, immediate network-level access control without manual steps.
✓ Why A is correctLaunch templates natively support security group assignment, ensuring all new instances receive the same firewall rules automatically upon launch.
✗ Why B is wrongNACLs operate at the subnet level and filter traffic by IP address and port, but they cannot reference security groups as sources. Since the ALB's IP addresses can change as it scales, maintaining an accurate NACL rule based on ALB IPs is impractical. Security groups can reference the ALB's security group directly, which is more reliable.
✗ Why C is wrongA lifecycle hook with Lambda adds unnecessary complexity, introduces a window during which new instances are unprotected (between launch and Lambda execution), and creates a potential failure point. Launch templates already handle security group assignment natively at launch time.
✗ Why D is wrongAWS Config rules evaluate compliance after resources are created, meaning there is a gap between instance launch and remediation during which the instance lacks proper firewall rules. This is a reactive approach, whereas launch templates provide proactive, immediate security group assignment.
Quiz 3 — Sample Question
A company stores sensitive financial records in Amazon S3. A compliance audit requires that all data at rest be encrypted using encryption keys that the company fully controls, including the ability to rotate and disable keys. Which solution meets these requirements?
  • Use client-side encryption only
  • Store data unencrypted
  • Use S3-managed encryption keys (SSE-S3) only
  • ✓ Enable S3 default encryption with AWS KMS customer-managed keys (CMK)
Show Explanation
✓ Why correctEnabling S3 default encryption with AWS KMS customer-managed keys (CMKs) provides server-side encryption where the company retains full control over the key lifecycle—including rotation, disabling, and access policies. Key usage is logged via AWS CloudTrail for auditing, satisfying compliance requirements for customer-controlled encryption at rest.
✗ Why A is wrongClient-side encryption requires the application to handle encryption before upload. It does not enforce server-side encryption at the S3 storage layer, adds complexity, and cannot guarantee all upload paths (Console, CLI, SDKs) use encryption.
✗ Why B is wrongStoring data unencrypted directly violates the compliance requirement for encryption at rest.
✗ Why C is wrongSSE-S3 uses keys fully managed by AWS. The company has no ability to control rotation, set key policies, or audit individual key usage—failing the requirement for customer-managed keys.
✗ Why D is wrongThis is the correct answer.
Quiz 4 — Sample Question
A growing e-commerce company has multiple development teams deploying applications on AWS. The security team must implement IAM best practices to reduce credential compromise risk and enforce access control across the organization. Which THREE actions should they take? (Choose three.)
  • Rotate access keys every 90 days and disable unused keys
  • Share root account credentials with team leads for emergency access
  • ✓ Use IAM roles for applications running on EC2 instead of embedding access keys
  • Grant all developers PowerUserAccess to simplify policy management
  • ✓ Enable MFA for all IAM users with privileged access
  • ✓ Implement least privilege by creating granular IAM policies scoped to specific resources
Show Explanation
✓ Why correctUsing IAM roles for applications eliminates the need to manage long-lived access keys, reducing credential exposure risk. MFA adds a second authentication factor that protects privileged accounts even if passwords are compromised. Granular least-privilege policies ensure each identity can only perform actions required for its function, limiting the blast radius if credentials are compromised.
✗ Why A is wrongWhile rotating access keys is a good hygiene practice, it is not one of the top three foundational IAM best practices. The AWS Well-Architected Framework prioritizes eliminating long-lived credentials entirely (via IAM roles) over simply rotating them on a schedule.
✗ Why B is wrongRoot account credentials should never be shared. AWS recommends protecting the root user with MFA and using it only for tasks that specifically require root access (such as changing account support plans or closing the account).
✗ Why D is wrongPowerUserAccess grants broad permissions for all AWS services except IAM user and group management. This violates the principle of least privilege because developers should only have permissions required for their specific tasks and projects.
Quiz 5 — Sample Question
A company is migrating a legacy application to AWS. The development team has containerized the application but does not want to manage the underlying infrastructure or cluster capacity. The application has unpredictable traffic patterns. Which solution meets these requirements with the LEAST operational overhead?
  • Amazon ECS with EC2 launch type and an Auto Scaling group
  • ✓ Amazon ECS with AWS Fargate launch type
  • Amazon EKS with self-managed node groups
  • Amazon EC2 instances running Docker containers directly
Show Explanation
✓ Why correctAWS Fargate is a serverless compute engine for containers that works with both Amazon ECS and Amazon EKS. It removes the need to provision and manage servers, lets you specify and pay for resources per application, and automatically scales compute capacity based on demand. This is ideal for unpredictable traffic since there is no cluster capacity to manage.
✗ Why A is wrongAmazon ECS with the EC2 launch type requires you to manage and scale the underlying EC2 instances yourself, including patching, capacity planning, and cluster management. This adds significant operational overhead.
✗ Why C is wrongAmazon EKS with self-managed node groups requires managing EC2 instances as worker nodes, including scaling, patching, and OS maintenance. While EKS manages the Kubernetes control plane, the data plane (worker nodes) still requires infrastructure management.
✗ Why D is wrongRunning containers directly on EC2 instances with Docker provides no orchestration, no automatic scaling, and requires full infrastructure management including health checks, load distribution, and instance lifecycle management.
Quiz 6 — Sample Question
A company runs a serverless application using AWS Lambda functions that connect to an Amazon RDS MySQL database. During peak traffic, the database frequently reaches its maximum connection limit, causing intermittent application errors. The Solutions Architect needs a solution that improves database availability without modifying the Lambda function code. What should the architect recommend?
  • Upgrade to a larger RDS instance class with more memory
  • Enable RDS Multi-AZ to distribute connection load across instances
  • ✓ Place Amazon RDS Proxy between the Lambda functions and the database
  • Switch to Amazon DynamoDB to eliminate connection limits
Show Explanation
✓ Why correctAmazon RDS Proxy manages a pool of database connections and shares them across Lambda function invocations, preventing connection exhaustion. It sits between the application and the database, requires no application code changes, and automatically multiplexes many application connections over fewer database connections.
✗ Why A is wrongUpgrading the instance class increases compute and memory but does not significantly increase the maximum number of database connections. The root cause is connection management from many concurrent Lambda invocations, not resource capacity on the database.
✗ Why B is wrongRDS Multi-AZ provides a synchronous standby replica for failover, but the standby does not serve traffic or accept connections. It does not help with connection pooling or distributing active connections across instances.
✗ Why D is wrongMigrating to DynamoDB eliminates relational database connection limits, but it requires re-architecting the application data model and Lambda code, which contradicts the requirement of no code changes. DynamoDB is not a drop-in replacement for a relational database.
Quiz 7 — Sample Question
A company is building an e-commerce platform where each order must be processed simultaneously by an inventory service, a billing service, and a notification service. Each service processes messages at different rates. Which architecture ensures all three services receive every order message and can process independently?
  • A single Amazon SQS standard queue with all three services polling for messages
  • An Amazon Kinesis Data Stream with three separate consumer applications
  • Three separate Amazon SQS queues with the application publishing to each queue directly
  • ✓ An Amazon SNS topic with three Amazon SQS queue subscriptions, one per service
Show Explanation
✓ Why correctAn SNS topic acts as a fan-out mechanism. When a message is published, SNS delivers a copy to every subscribed SQS queue. Each service consumes from its own dedicated queue independently, enabling different processing rates and independent retry logic without affecting the others.
✗ Why Option A is wrongA single SQS standard queue delivers each message to only one consumer. Multiple services polling the same queue would compete for messages rather than each receiving a copy, so not all three services would process every order.
✗ Why Option B is wrongWhile Amazon Kinesis Data Streams supports multiple consumers reading the same stream, it requires each consumer to manage shard iterators and checkpointing. Kinesis is optimized for high-throughput ordered streaming rather than simple fan-out to independent services with varying processing rates. It also has higher cost for this use case.
✗ Why Option C is wrongHaving the application publish directly to three separate queues creates tight coupling between the publisher and every downstream service. Adding or removing a service requires changing the publisher code, violating loose coupling principles.
Quiz 8 — Sample Question
A media company stores video files in Amazon S3. Analysis shows that files are frequently accessed for the first 30 days, then accessed only a few times per month for up to one year. Files older than one year are needed only for annual compliance audits, and retrieval within 3–5 hours is acceptable. Which TWO S3 storage classes should the Solutions Architect use in a lifecycle policy to minimize storage costs? (Select TWO.)
  • S3 One Zone-Infrequent Access for files older than 30 days
  • ✓ S3 Glacier Flexible Retrieval for files older than one year
  • S3 Standard for all files regardless of age
  • S3 Glacier Instant Retrieval for files older than 30 days
  • ✓ S3 Standard-Infrequent Access for files older than 30 days
Show Explanation
✓ Why correctS3 Standard-IA (E) provides the same millisecond access as S3 Standard at a lower per-GB storage cost, making it ideal for files accessed only a few times per month. S3 Glacier Flexible Retrieval (B) is the lowest-cost archival tier where 3–5 hour standard retrieval meets the annual audit requirement for files older than one year.
✗ Why A is wrongS3 One Zone-IA stores data in a single Availability Zone, reducing durability. If that AZ is lost, the data is permanently gone. For compliance video files that must be retained, Standard-IA provides the same cost model with full multi-AZ durability (11 nines).
✗ Why C is wrongKeeping all files in S3 Standard regardless of age is the most expensive approach. Files older than 30 days are rarely accessed, so paying the S3 Standard per-GB rate for them wastes budget when Standard-IA costs roughly 45% less per GB.
✗ Why D is wrongS3 Glacier Instant Retrieval provides millisecond access like Standard-IA and costs less per GB stored, but it charges significantly higher per-GB retrieval fees. It is optimized for data accessed roughly once per quarter. For the 30-day to one-year window where files are still accessed a few times per month, Standard-IA is more cost-effective due to lower retrieval costs.
Quiz 9 — Sample Question
A financial services company runs a tightly coupled high-performance computing (HPC) workload on Amazon EC2 that requires inter-instance latency below 2 milliseconds. The instances must communicate frequently during parallel computations. How should a Solutions Architect deploy these instances to meet the latency requirement?
  • ✓ Launch instances in a cluster placement group within a single Availability Zone
  • Launch instances in a spread placement group across multiple Availability Zones
  • Launch instances in a partition placement group to isolate hardware failures
  • Launch instances across two Availability Zones behind an Application Load Balancer
Show Explanation
✓ Why correctA cluster placement group places instances on the same high-bisection-bandwidth segment of the network within a single AZ, delivering the lowest inter-instance latency. This is the recommended placement strategy for tightly coupled HPC workloads that require frequent node-to-node communication.
✗ Why B is wrongA spread placement group distributes instances across distinct underlying hardware to reduce correlated failures. It is designed for high availability of small groups of instances, not for low latency. It also limits placement to 7 instances per AZ per group.
✗ Why C is wrongA partition placement group isolates groups of instances onto separate racks to limit blast radius of hardware failures. It is useful for large distributed workloads like HDFS or Cassandra, but does not optimize for the lowest possible inter-instance latency.
✗ Why D is wrongPlacing instances across multiple AZs introduces cross-AZ network latency (typically 1–2 ms round-trip), which would not reliably meet the sub-2-ms requirement for tightly coupled communication patterns.
Quiz 10 — Sample Question
A multinational e-commerce company runs its order management system on Amazon Aurora MySQL in us-east-1. European and Asian customers report read latencies exceeding 300 ms due to cross-Region network round trips. The company's disaster recovery plan requires that if us-east-1 becomes unavailable, a database in another Region must assume full read-write operations within one minute with minimal data loss. Which solution meets BOTH the latency and disaster recovery requirements?
  • Create Aurora read replicas within us-east-1 across multiple Availability Zones
  • ✓ Deploy an Aurora Global Database with secondary clusters in eu-west-1 and ap-northeast-1
  • Create cross-Region Amazon RDS for MySQL read replicas in eu-west-1 and ap-northeast-1
  • Migrate the database to Amazon DynamoDB global tables replicated across three Regions
  • Enable Aurora Multi-AZ deployment and use Amazon Route 53 latency-based routing
Show Explanation
✓ Why correctAurora Global Database replicates data to secondary clusters in other AWS Regions with typical replication lag under one second. Secondary clusters serve read traffic with local-Region latency, and in a Regional failure the secondary cluster can be promoted to read-write in under one minute.
✗ Why A is wrongMulti-AZ read replicas within us-east-1 provide high availability within a single Region but do nothing to reduce latency for users in Europe and Asia. They also cannot help if the entire us-east-1 Region becomes unavailable.
✓ Why B is correctAurora Global Database places read-capable secondary clusters in eu-west-1 and ap-northeast-1, reducing read latency to local-Region levels. Its managed cross-Region replication and fast promotion (typically under one minute) satisfy the disaster recovery requirement.
✗ Why C is wrongCross-Region RDS for MySQL read replicas can reduce read latency in remote Regions, but promoting an RDS read replica to a standalone primary is a manual process that takes several minutes, breaks the replication chain, and requires application endpoint reconfiguration. This does not meet the one-minute failover requirement.
✗ Why D is wrongDynamoDB global tables provide multi-Region active-active replication, but migrating from Aurora MySQL to DynamoDB requires redesigning the data model for NoSQL and rewriting all SQL queries—a disproportionate change for a relational workload.
✗ Why E is wrongAurora Multi-AZ provides automatic failover within a single Region, not across Regions. Route 53 latency-based routing directs users to the nearest endpoint but does not create database replicas in other Regions or reduce database query latency for remote users.
Quiz 11 — Sample Question
A company is launching a web application that requires public-facing web servers and backend databases in private subnets. The architecture must remain operational if an entire Availability Zone fails. Which combination of components should a Solutions Architect implement?
  • An Internet Gateway, a single NAT Gateway in one AZ, and route tables for public and private subnets
  • ✓ An Internet Gateway, a NAT Gateway in each AZ, and route tables configured for each subnet tier
  • Multiple Internet Gateways (one per AZ), a single NAT Gateway, and a default route table
  • An Internet Gateway, NAT instances in each AZ, and a single shared route table for all subnets
Show Explanation
✓ Why correctAn Internet Gateway (one per VPC) enables public subnet internet access. Deploying a NAT Gateway in each AZ ensures that private subnet instances retain internet connectivity even if one AZ fails. Separate route tables per subnet tier allow correct traffic routing — public subnets route 0.0.0.0/0 to the IGW, while each private subnet routes 0.0.0.0/0 to its AZ-local NAT Gateway.
✗ Why A is wrongA single NAT Gateway in one AZ is a single point of failure. If that AZ experiences an outage, all private subnet internet access across the VPC is lost, violating the high availability requirement.
✗ Why C is wrongA VPC supports only one Internet Gateway — you cannot attach multiple IGWs to the same VPC. Additionally, a single default route table cannot differentiate routing between public and private subnets, preventing correct traffic flow.
✗ Why D is wrongNAT instances are self-managed EC2 instances that lack the automatic scaling, built-in redundancy, and high availability of managed NAT Gateways. A single shared route table also prevents the necessary routing separation between public and private subnets.
Quiz 12 — Sample Question
A retail company receives 200 GB of point-of-sale transaction data nightly via batch uploads and also captures real-time clickstream data at 5,000 events per second from its website. A Solutions Architect is selecting the AWS ingestion services. Which TWO factors are MOST important when choosing between ingestion approaches?
  • ✓ Data velocity — whether data arrives as real-time streams or in scheduled batches
  • The specific file encoding used by the source systems (for example, UTF-8 vs. ASCII)
  • The data format at the source — whether it is structured, semi-structured, or unstructured
  • The number of downstream consumers that will query the ingested data
  • ✓ Data volume and throughput — the total size and sustained rate of data to be ingested
Show Explanation
✓ Why correct (A, E)Data velocity determines whether a streaming service (Amazon Kinesis Data Streams) or a batch transfer service (AWS DataSync) is needed. Data volume and throughput determine the capacity, scaling configuration, and service tier required — for example, whether the Snow Family is needed for offline bulk transfer or whether Kinesis shard counts must be scaled up. Together these two factors are the primary drivers of ingestion architecture.
✗ Why B is wrongFile encoding (UTF-8 vs. ASCII) is a parsing-level detail handled during transformation, not a factor that drives the choice between streaming and batch ingestion services.
✗ Why C is wrongSource data format (structured, semi-structured, or unstructured) affects the transformation and query layers downstream, but it does not determine the ingestion approach. Both Kinesis and DataSync can ingest any data format; format-specific processing occurs after ingestion.
✗ Why D is wrongThe number of downstream consumers affects the analytics and query architecture (for example, choosing Redshift vs. Athena), but it does not influence whether data should be ingested via real-time streaming or scheduled batch transfer.
Quiz 13 — Sample Question

  • ✓ Amazon EFS with Max I/O performance mode
  • Amazon EBS Multi-Attach io2 volume shared across all instances
  • Amazon FSx for Windows File Server with SMB shares
  • Amazon S3 accessed via the AWS CLI from each instance
Show Explanation
✓ Why correctAmazon EFS with Max I/O performance mode is designed for highly parallelized workloads where large numbers of EC2 instances need concurrent shared file access. Max I/O mode scales to higher aggregate throughput and IOPS across many NFS clients, which is ideal for 50 instances processing video files concurrently.

Quiz 14 — Sample Question
A company runs development and testing workloads on Amazon EC2 instances using General Purpose SSD (gp2) Amazon EBS volumes. The workloads require moderate IOPS, but the team has noticed they are overpaying for storage. A Solutions Architect needs to reduce EBS costs without negatively impacting application performance. What should the Solutions Architect recommend?
  • Migrate all volumes to Throughput Optimized HDD (st1) for lower per-GB pricing
  • ✓ Migrate all volumes to General Purpose SSD (gp3) and adjust IOPS and throughput to match workload needs
  • Migrate all volumes to Provisioned IOPS SSD (io2) to maximize performance consistency
  • Increase the size of the existing General Purpose SSD (gp2) volumes to improve burst performance

This lets the team right-size performance to actual workload needs while reducing cost.

Quiz 15 — Sample Question
A company runs a content management application on Amazon EC2 that averages 10% CPU utilization but periodically bursts to 70% during content publishing events. The workload is steady-state most of the time. A Solutions Architect needs to minimize compute costs while maintaining acceptable performance during bursts. Which instance type is MOST cost-effective?
  • ✓ T3 burstable instances that provide a baseline CPU level with the ability to burst using accumulated CPU credits
  • C6i compute-optimized instances sized for peak CPU demand
  • M6i general-purpose instances with consistent high CPU capacity
  • R6i memory-optimized instances with higher vCPU allocation

✓ Why correctT3 burstable instances are designed for workloads with low average CPU utilization and occasional spikes. They accumulate CPU credits during idle periods and spend them during bursts, providing cost-effective performance for exactly this usage pattern.
✗ Why B is wrongC6i compute-optimized instances are built for sustained high-CPU workloads such as batch processing and HPC. Using them for a workload averaging only 10% CPU means paying for unused compute capacity the vast majority of the time.

Quiz 16 — Sample Question
A retail company stores order history data in Amazon DynamoDB. The data is written once when an order completes and accessed only a few times per month for customer support lookups. Storage currently accounts for 70% of the table's monthly cost. What should a Solutions Architect recommend to reduce costs?
  • Enable DynamoDB Accelerator (DAX) to reduce read costs on older items
  • ✓ Switch the table to the DynamoDB Standard-Infrequent Access table class
  • Migrate the data to Amazon RDS MySQL for lower storage pricing
  • Reduce the provisioned write capacity units on the table
Show Explanation
✓ Why correctThe DynamoDB Standard-Infrequent Access (Standard-IA) table class reduces storage costs by up to 60% compared to the Standard table class. It is designed for tables where storage is the dominant cost and data is accessed infrequently. Since order history is written once and read only a few times per month with storage comprising 70% of the cost, Standard-IA is the optimal choice.
✗ Why A is wrongDynamoDB Accelerator (DAX) is an in-memory caching layer that reduces read latency and read capacity consumption. Since the table is already infrequently accessed, DAX would add cost without meaningful benefit and does not reduce storage costs.
✗ Why C is wrongMigrating to Amazon RDS MySQL introduces operational overhead for schema management, patching, and scaling. DynamoDB Standard-IA achieves the storage savings natively without requiring a migration or data model changes.
✗ Why D is wrongReducing write capacity units addresses write throughput cost, not storage cost. Since storage accounts for 70% of the bill, this approach targets the wrong cost component.
Quiz 17 — Sample Question
A company runs application servers in private subnets that generate 10 TB of log data per month sent to Amazon CloudWatch Logs through a NAT Gateway. The NAT Gateway data processing charges for this CloudWatch traffic alone exceed $450 per month. Which change provides the MOST cost savings for this traffic?
  • Replace the NAT Gateway with a NAT instance on a t3.micro to reduce the hourly and per-GB charges for all outbound traffic
  • Deploy an additional NAT Gateway in a second Availability Zone to distribute the CloudWatch traffic processing load
  • ✓ Create interface VPC endpoints for CloudWatch Logs in each Availability Zone used by the application servers
  • Move the application servers to public subnets with Elastic IP addresses so log traffic reaches CloudWatch without a NAT Gateway
Show Explanation
✓ Why correct (C)Interface VPC endpoints for CloudWatch Logs charge ~$0.01/hr per AZ plus ~$0.01/GB processed. At 10 TB/month, the endpoint data processing cost is approximately $100 plus roughly $7/AZ/month in hourly charges. Compared to the NAT Gateway's ~$0.045/GB ($450 at 10 TB) plus ~$32/month hourly, the interface endpoint saves over $300/month for this traffic alone. The traffic bypasses the NAT Gateway entirely, routing directly to CloudWatch through the endpoint's elastic network interface within the VPC.
✗ Why A is wrongA NAT instance on t3.micro (~$7.60/month on-demand) is cheaper than NAT Gateway hourly charges, but it has limited network bandwidth (~5 Gbps burst on t3 family) and lacks automatic scaling, high availability, and managed patching. For 10 TB/month of continuous log traffic, a t3.micro may throttle during peaks. More importantly, a NAT instance still processes all outbound traffic through a single point, while an interface endpoint selectively removes only CloudWatch traffic from the NAT path—leaving the NAT Gateway properly sized for remaining traffic.
✗ Why B is wrongAdding a second NAT Gateway distributes load but does not reduce total per-GB processing charges. NAT Gateway charges ~$0.045/GB regardless of how many gateways process the traffic. Two gateways processing 5 TB each still cost $450 total in per-GB charges, plus double the hourly fees (~$64/month instead of ~$32/month), increasing overall costs.
✗ Why D is wrongMoving servers to public subnets eliminates NAT Gateway charges but removes the security isolation of private subnets. The application servers would be directly addressable from the internet, requiring additional security hardening. Interface VPC endpoints achieve the same NAT Gateway cost elimination for CloudWatch traffic while preserving the private subnet security model.
Quiz 18 — Sample Question
A company operates 50 microservices across three AWS accounts. Monthly cloud spend has grown 40% quarter-over-quarter, and the CTO asks the Solutions Architect to establish a cost governance strategy. Which THREE actions should the Solutions Architect take FIRST? (Choose three.)
  • Negotiate an Enterprise Discount Program agreement with AWS to secure volume-based pricing discounts across all three accounts
  • ✓ Enable cost allocation tags and enforce tagging policies across all accounts
  • ✓ Analyze spending trends in AWS Cost Explorer and enable rightsizing recommendations
  • Purchase 3-year All Upfront Reserved Instances for every running EC2 instance immediately
  • ✓ Set up AWS Budgets with alerts for each account and project
  • Consolidate all three AWS accounts into a single account to simplify billing and eliminate cross-account data transfer charges
Show Explanation
✓ Why correctBefore committing to long-term purchasing decisions, the company must first gain cost visibility. Enabling cost allocation tags (B) lets teams categorize spend by project and department. Cost Explorer with rightsizing recommendations (C) identifies waste and underutilized resources. AWS Budgets with alerts (E) provides proactive spending thresholds so teams are notified before budgets are exceeded. Together these three actions establish the governance foundation required before making optimization decisions.
✗ Why A is wrongThe Enterprise Discount Program (EDP) requires a committed annual spend and is a long-term financial commitment. Without first understanding where the 40% cost growth is coming from, committing to an EDP risks locking in spending on resources that may be over-provisioned or unnecessary. The company needs cost visibility through tagging, Cost Explorer, and Budgets before negotiating volume discounts.
✓ Why B is correctCost allocation tags are foundational to cost governance. They enable grouping and filtering costs by project, team, or environment in Cost Explorer and the AWS Cost and Usage Report. Without tags, the company cannot attribute the 40% cost growth to specific services or teams.
✓ Why C is correctAWS Cost Explorer provides historical and forecasted cost views, while its rightsizing recommendations analyze CloudWatch metrics to identify over-provisioned EC2 instances. This addresses the immediate need to understand where money is being spent.
✗ Why D is wrongPurchasing 3-year All Upfront RIs without first analyzing usage patterns risks locking into commitments for resources that may be over-provisioned, underutilized, or candidates for elimination. The company should first understand baseline utilization through Cost Explorer before making long-term purchasing commitments.
✓ Why E is correctAWS Budgets enables setting custom cost thresholds with automated alerts via SNS or email. This gives each team proactive warnings before overspending, which directly addresses the governance gap that allowed 40% uncontrolled cost growth.
✗ Why F is wrongConsolidating multiple AWS accounts into one eliminates the organizational and security benefits of multi-account architecture, such as blast radius isolation and independent IAM boundaries.
